# TikTok Saved Recipe Intake Design

Approval Source: Marcus said "Yes proceed" after the recommendation to start with a recipe-first TikTok workflow plus a small archive layer.

## Objective

Add a read-only v0 workflow that turns Marcus's saved/favorited TikToks into local, searchable recipe and tips artifacts without mutating TikTok, posting, following, liking, deleting, shopping, calendar, or publishing anything.

## Scope

This v0 focuses on:

- Read-only extraction from a persistent TikTok browser profile.
- Raw saved/favorite inventory records.
- Deterministic normalization and classification into recipes vs general tips.
- Family-useful recipe cards and a weekly digest.
- Local output under `/app/output/tiktok/`, synced to the live browser-agent runtime by the existing source-to-live process.

This v0 does not include:

- Scheduled cron execution.
- TikTok account mutation.
- Auto-publishing to social platforms.
- Grocery ordering.
- Calendar writes.
- Official TikTok API integration.
- Guaranteed audio/video transcription. Transcript/caption extraction is best-effort and must degrade cleanly.

## Existing State

The browser-agent repo already has:

- Docker/Playwright automation with persistent browser profiles.
- Canonical Docker test runner: `docker compose run --rm browser-agent scripts/run_tests.py`.
- X bookmark processing in `scripts/process_bookmarks.py` with dry-run default, output artifacts, LLM analysis, link/media enrichment, and safety gates.
- Runtime/source split: source repo at `/home/orchestrator/repos/local/browser-agent`, live runtime at `/home/orchestrator/browser-agent`.
- Existing sync helper: `scripts/sync_to_live.sh`.

The TikTok workflow should reuse these patterns rather than introduce a new service.

## Architecture

Create a separate TikTok-specific script instead of expanding the X bookmark processor. The new script owns TikTok navigation, extraction, normalization, classification, and report generation.

Core files:

- `scripts/process_tiktok_saves.py`
  - Launches Playwright persistent context with `profiles/tiktok-profile`.
  - Opens TikTok saved/favorites pages in read-only mode.
  - Collects video cards and visible metadata.
  - Normalizes records into stable dictionaries.
  - Classifies each record into recipe or tip categories.
  - Writes JSONL/JSON/Markdown artifacts.

- `tasks/test_tiktok_saves.py`
  - Tests deterministic URL normalization, record extraction helpers, recipe classification, tip classification, recipe card generation, digest generation, and output path safety.

- `README.md`
  - Documents attended TikTok login and read-only run commands.

The first implementation should keep browser scraping logic thin and move deterministic transforms into pure functions so tests can verify behavior without a live TikTok session.

## Data Flow

1. Marcus performs attended login once using the existing VNC pattern into `profiles/tiktok-profile`.
2. `process_tiktok_saves.py --dry-run --max N` launches Chromium with that profile.
3. The script visits TikTok saved/favorites pages.
4. The script extracts visible cards and detail-page metadata when safely available.
5. Each item is normalized into a raw record.
6. Pure deterministic functions classify likely recipes and tips.
7. Optional LLM analysis creates structured family-useful notes from captions/transcripts/visible text.
8. The script writes artifacts under `/app/output/tiktok/`:
   - `raw_saves.jsonl`
   - `recipes.jsonl`
   - `tips.jsonl`
   - `weekly_digest.md`
   - `grocery_list.md`
   - `run_summary.json`

## Record Contract

Raw save record fields:

- `source`: always `tiktok`
- `url`: canonical TikTok video URL when available
- `video_id`: extracted ID when available, otherwise stable hash fallback
- `creator_handle`: creator handle when visible
- `creator_name`: creator display name when visible
- `caption`: visible caption text
- `hashtags`: list of hashtag strings without `#`
- `saved_at`: null unless TikTok exposes a reliable saved timestamp
- `collected_at`: ISO timestamp generated by the script
- `text_context`: combined visible text used for classification
- `media_type`: `video`
- `extraction_status`: `ok`, `partial`, or `error`
- `extraction_notes`: non-secret reason when partial/error

Recipe card fields:

- `id`
- `source_url`
- `title`
- `creator_handle`
- `category`
- `family_fit`: `high`, `medium`, or `low`
- `confidence`: `high`, `medium`, or `low`
- `ingredients`
- `steps`
- `time_estimate_minutes`
- `servings_estimate`
- `grocery_categories`
- `prep_ahead_notes`
- `kid_friendly_notes`
- `why_try_this`

Tip card fields:

- `id`
- `source_url`
- `title`
- `creator_handle`
- `category`
- `summary`
- `actionable_next_step`
- `family_or_household_relevance`
- `confidence`

## Classification Rules

Recipe signals:

- Food words: recipe, dinner, lunch, breakfast, snack, meal prep, chicken, beef, pasta, rice, air fryer, crockpot, grill, oven, bake, sauce, ingredients.
- Hashtags such as foodtok, dinnerideas, mealprep, recipe, easyrecipe, familydinner, airfryer.
- Step language: mix, bake, cook, simmer, add, chop, season, serve.

Tip signals:

- Household or general-use words: hack, tip, idea, organize, clean, travel, parenting, productivity, routine, setup.
- Non-food posts with actionable advice.

If a post matches both recipe and tip signals, recipe wins only when food/ingredient/cooking terms are present. Otherwise classify as tip.

If confidence is low, keep the item in `tips.jsonl` with category `review` rather than deleting or hiding it.

## Safety and Privacy

- Default mode is `--dry-run`; there is no TikTok execute/mutation mode in v0.
- The script must not click like, favorite, save, follow, comment, share, delete, or message controls.
- Browser profile contents stay in `profiles/` and remain ignored by Git.
- Output must not include cookies, localStorage, authorization headers, raw browser profile paths, or full page HTML.
- Failures caused by expired login produce `requires_user` status and exit successfully only when the failure is expected and clearly reported.
- Unexpected infrastructure/code failures exit non-zero.

## Error Handling

- If TikTok requires login: write `run_summary.json` with `status: requires_user`, do not retry aggressively, do not attempt credential entry.
- If selectors drift: write `status: partial` or `status: extraction_failed` with screenshot/proof path if available, then exit non-zero for code/selector failures.
- If individual videos fail extraction: keep partial raw record with `extraction_status: partial`; continue processing remaining items.
- If LLM analysis fails: preserve raw records and deterministic classification, mark card confidence low, and include error count in summary.
